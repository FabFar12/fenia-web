# ADR-029 — Private internal metrics: own visit counter and owners' accounts

## Status
Accepted (2026-11-14, decisions of the dev). Supersedes the **analytics** layer of [ADR-024](./ADR-024-observability-on-hostinger.md) (Plausible is not used). ADR-024's uptime monitoring (UptimeRobot) stays, and its error tracking (Sentry) stays deferred. Proposal and research: [docs/ventas/propuesta-metricas.md](../ventas/propuesta-metricas.md).

## Context

The dev asked for a metrics section only the dev and Fab can see, covering the site and the kit sales. Three constraints came out of the conversation:

- **Every number must stay private to FENIA** ("toda la info tiene que ser privada para nosotros"). No third-party analytics.
- **Visits must be measured.** Until now nothing measured them: ADR-024 chose Plausible but it was never activated.
- **Entry with user and password**, as a first piece of the FENIA ecosystem (D25: buyers' accounts come in phase 2).

The research ([propuesta-metricas.md](../ventas/propuesta-metricas.md)) found that Plausible's USD 9 plan has no API, funnels or revenue, and that Umami's free plan has no API and no team members. Neither can put visits and sales on one private screen, and both send the data to a third party.

## Decision

1. **Own visit counter.** Every page sends one beacon per page view (and per WhatsApp click) to `/api/hit.php` with `navigator.sendBeacon`. The site's `ClientRouter` navigations are counted with `astro:page-load`.
   - **No cookies, nothing personal.** Stored: the page path, the source (referrer host or `utm_*`), the campaign, phone/tablet/computer (from the window width), and a visitor hash = HMAC(IP + browser) keyed with **the day**. Within a day it tells visitors apart; across days nobody can be followed (Plausible's method). No IP, no user agent, no query string, no hash fragment (`/descarga/#t=…` sends only `/descarga/`).
   - Not counted: bots (user-agent filter), automated browsers (`navigator.webdriver`, so our E2E tests do not pollute the data), the `/metricas/` page, and the owners while logged in (readable cookie `fm_owner=1`, which holds no secret).
   - Kept 400 days, then deleted by the hourly job. Max 300 events per IP per hour.
2. **Owners' accounts with user and password.** The users and their password hashes (`password_hash`, bcrypt) live in the server config (`owners`), never in git. The plaintext passwords are generated by the dev's machine and live only in `~/fenia-secrets/<env>/`.
   - Session: a random 256-bit token in an `HttpOnly`, `Secure`, `SameSite=Strict` cookie, valid only for `/api/`, for 30 days; only its SHA-256 is stored, in a generic `sessions` table (subject `owner:<user>`), ready for buyers in D25 phase 2. Logging out deletes it; removing a user from the config kills its sessions.
   - Guessing is capped: 10 attempts per IP every 15 minutes and 10 per user per hour. A wrong password and an unknown user get the same answer, in the same time.
3. **One screen, `/metricas/`.** Static page (noindex, outside the sitemap) that holds no data; it asks `/api/metricas.php`, which answers only with an owner's session. Sections: visits, purchase funnel (from the day the counter started), sales, how buyers use "Tu kit", latest sales (masked emails) and the site's speed.
4. **Free external checks, outside the screen.**
   - **Speed:** once a day the hourly job asks PageSpeed Insights (phone) for the home and a kit page, and keeps the score and the Core Web Vitals. These are public pages, so no private data leaves.
   - **Uptime:** UptimeRobot (free, commercial use allowed since June 2026), from the dev's account.
   - **Google searches:** Google Search Console, from the dev's account.

## Consequences

- One private place where visits and sales meet: the funnel "saw a kit → went to pay → paid" by kit, at no monthly cost.
- First-party beacons are rarely blocked by ad blockers, unlike third-party analytics.
- More code to maintain (counter, sessions, report), covered by PHPUnit (MetricsTest, CronTest), the security suite (S-40…S-45) and E2E.
- No map by country (no IP geolocation database). It can be added later without storing IPs.
- The privacy policy must mention the cookieless visit counter: pending with the lawyer (docs/ventas, Bloque 5).
- Schema 3 adds `site_events`, `sessions` and `speed_checks`; it migrates itself on the first request after the deploy.
